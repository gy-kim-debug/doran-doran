1. 개요

No항목작성 내용
1-1영역 소셜/커뮤니티 (가족 전용 SNS)

가족·소모임 단위의 비공개 SNS 영역입니다. 불특정 다수에게 열린 공개형 SNS와 달리 초대받은 구성원만 참여하는 닫힌 구조라, 서비스 초기에도 안정적으로 운영할 수 있습니다.
1-2서비스명

① 서비스명 — 도란도란

② 소개 — 매일 하나의 질문으로 시작해 가족들이 소식을 올리고 서로 확인·반응하는 가족 전용 SNS.
1-3아이디어 개요 같이 살거나 자주 연락해도 서로의 하루를 나눌 계기가 없어 그냥 흘러가 버리는 가족의 일상을 해결하기 위해, 매일 하나의 질문을 던지고 가족끼리만 보는 닫힌 피드에 소식을 올려 서로 확인하고 반응하는 가족 전용 SNS를 만듭니다. 일반 메신저처럼 대화가 흘러가 사라지는 대신, 누가 읽었는지·어떤 반응을 남겼는지가 쌓이고 정리되며 일정·할 일까지 한곳에서 해결됩니다.
1-4기대 효과 가족이 소식을 나눌 계기 자체가 없다는 공백을 메우는 가족 전용 SNS입니다.
  • 이용자 — 매일 하나의 가벼운 질문이 기록을 남기는 부담을 낮추고, 그렇게 쌓인 기록이 가족만의 아카이브가 됩니다. 일정·할 일까지 한 앱에서 해결되어 매일 다시 열어볼 이유를 만듭니다.
  • 사업 — 매일 재방문을 만드는 습관형 서비스로 먼저 활성 사용자를 확보하고, 이후 다양한 방식으로 수익화할 수 있는 기반을 마련합니다.

2. 비즈니스 임팩트

No항목작성 내용
2-1시장 분석 "가족이 소식을 나눌 계기가 없다"는 빈틈은 구조적으로 커지고 있고, 가족끼리만 모여 매일 소식을 올리고 확인·반응하는 닫힌 SNS는 아직 비어 있습니다.
  • 수요 배경 — 1인가구 804.5만(전체 36.1%, 역대 최고)·맞벌이 608.6만으로 가족이 실시간으로 얼굴을 맞댈 시간이 구조적으로 줄고 있습니다. [2025.12 국가데이터처] 가족 단위 공유 도구 수요는 캘린더 앱 TimeTree 글로벌 7,000만+ 사용자로 이미 검증됐습니다. [TimeTree 공식 소개]
  • 차별점 — 일반 메신저의 가족 단체방은 대화가 흘러가고 기록으로 안 남으며, 가족 캘린더 앱은 일정 공유만 제공합니다. 매일 질문으로 가볍게 소식을 올리고 가족끼리 확인·반응하는 흐름은 경쟁 서비스에 없는 빈 자리입니다.
2-2고객 타겟
(시나리오)

타깃 — 서로의 일상을 나누고 싶은 가족·소모임(부모-자녀, 형제자매, 친척 모임, 반려동물·취미 모임 포함). 성장 엔진은 가족 챙기기를 자처하는 30~40대.

시나리오 — 저녁 무렵, 온 가족에게 "오늘 하루 중 제일 힘들었던 순간은 언제였나요?"라는 오늘의 질문이 도착합니다. 엄마는 반찬 사진과 함께 답을 남기고, 딸은 퇴근길 카페에서 짧은 글을 남깁니다. 각자 글을 올리면 다른 가족이 바로 확인하고 이모지 반응과 댓글을 남깁니다. 서로 시간을 맞추지 않아도 오늘 하루가 가족 모두에게 자연스럽게 공유됩니다.

진입 트리거 — "가족·소모임을 새로 챙기기 시작하는 시점"에 앱 설치로 이어집니다.

  • 명절 직후 — 오랜만에 모인 가족이 다시 흩어지면서 소통을 이어갈 채널이 필요해지는 시점.
  • 자녀 자취·입학, 새 학기 — 따로 살기 시작하며 서로의 일상을 확인할 방법이 필요해지는 시점.
  • 반려동물 입양, 손주 출생 — 새 가족 구성원의 일상을 자주 공유하고 싶어지는 시점.
  • 친척 모임·여행 준비 — 사촌 모임이나 가족 여행처럼 일정을 나눠야 하는 소모임이 새로 생기는 시점.
2-3비즈니스 모델 지금은 사용자 기반을 먼저 확보하는 데 집중하고, 본격적인 수익화는 이후 단계에서 검토합니다.
  • 1단계(지금) — 핵심 기능은 전부 무료로 제공합니다. 매일 질문으로 가볍게 기록을 남기는 습관을 만들어 활성 가족 수를 늘리는 데 집중하며, 가족방 개수·인원 한도를 넘을 때만 결제하는 이용권과 쌓인 기록을 실물로 남기고 싶을 때 구매하는 포토북을 함께 제공합니다.
  • 2단계(이후, 예시) — 사용자 기반이 쌓이면 업체와의 이벤트 제휴, 광고 등 다양한 방식을 추가로 검토합니다. 특정 모델을 미리 확정하지 않고, 쌓인 사용 패턴에 맞춰 결정합니다.

3. 개발 목표 및 AI 활용도

데모 결과물(코어) — 아이폰에서 실제로 동작하는 웹뷰 기반 iOS 앱: 가족방 생성·초대 → 오늘의 질문 노출 → 글쓰기(오늘 기록하기) → 오늘의 피드 → 가족 일정·공동 할 일.

하이라이트 — 한 가족이 글을 올리면 다른 가족 구성원이 바로 읽음 확인·반응·댓글을 남기는 흐름을 아이폰 2~3대로 동시에 시연합니다. "올리면 가족이 바로 안다"는 핵심 가치를 실제 기기 화면으로 보여줍니다.

No항목작성 내용
3-1사전준비기간
(8/20~21)		 구현 목표: 40%

결과물 — 아이폰 실기기에서 실행되는 웹뷰 기반 iOS 앱 골격.

  • 앱 셸 — WKWebView를 탑재한 iOS 프로젝트 구성, 웹 화면 로딩 및 하단 탭 네비게이션 연결.
  • 화면 — 가족방 생성·초대, 오늘의 질문 노출, 오늘 기록하기(글·사진 첨부), 오늘의 피드까지 주요 화면 UI 구현.
  • 서버 — 회원·가족방·게시물 데이터 모델과 기본 CRUD API 연동.
3-2스프린톤 데이
(8/25~26)		 구현 목표: 85%

결과물 — 아이폰 2~3대로 가족 구성원 흐름을 실제 시연할 수 있는 iOS 앱.

  • 핵심 상호작용 — 한 명이 글을 올리면 다른 구성원 기기에 읽음 확인·이모지 반응·댓글이 실시간 반영되는 흐름 완성.
  • 매일 질문 — 질문 뱅크 기반 자동 로테이션과 지정 시간 푸시 알림(네이티브 연동), 알림 탭 시 기록 화면 진입.
  • 부가 기능 — 가족 일정(생일 자동 등록 포함), 공동 할 일 담당자 지정·완료 체크, 추억 모아보기(월별).
3-3AI 활용 전략 AI는 결과물 안에서는 선택적 편의 기능으로, 개발 과정에서는 구현 속도를 높이는 용도로 활용합니다.
  • 결과물 내 AI — 매일 질문 자동 생성·로테이션(주제가 겹치지 않도록 질문 뱅크 관리), 답변 작성 보조(짧은 글도 편하게 남기도록 문장 힌트 제안), 일정 기간 가족 피드 요약. 없어도 서비스는 성립하는 편의 기능입니다.
  • 개발 과정 AI — Claude Code와 Codex를 병행해 스프린톤 기간 내 구현 속도를 높입니다.
    • Claude Code — 프로젝트 구조 설계, iOS 앱 셸·웹 프론트·백엔드 API 뼈대 구현, 화면 단위 코드 생성, 리팩터링·디버깅.
    • Codex — 반복 코드 작성과 단위 테스트 보조로 병렬 작업. 두 도구를 작업 성격에 따라 나눠 쓰고 결과를 교차 검토합니다.
    • 공통 — UI 목업·컴포넌트 시안 생성, 질문 세트·가족 대화 예시 등 시연용 더미 데이터 제작.
